# ArveMaa

Административная панель для выставления и хранения счетов.
Интерфейс на русском, эстонском или английском; сами счета печатаются на эстонском или английском — независимо от языка панели.
Next.js 16 (App Router) · Prisma · SQLite локально / PostgreSQL в проде · Tailwind v4.

## Что умеет

- **Логин** по e-mail и паролю (JWT в httpOnly-cookie, пароли — bcrypt).
- **Профиль** (`/settings`): свои данные для входа — имя, e-mail, смена пароля с подтверждением текущего — и **язык интерфейса** (русский / эстонский / английский). Язык хранится в аккаунте и восстанавливается при входе с любого устройства.
- **Язык документа** выбирается на каждом счёте — эстонский или английский. Панель при этом остаётся русской. Язык по умолчанию задаётся в настройках компании и подставляется в новый счёт.
- **Изолированные аккаунты**: каждый пользователь видит только свои компании, своих клиентов и свои счета. Роль ADMIN даёт только управление пользователями — не доступ к их данным.
- **Админка пользователей** (`/admin`, только для роли ADMIN): создание, смена роли, сброс пароля, деактивация.
- **Мультибизнес**: сколько угодно компаний в рамках своего аккаунта, переключатель в хедере. У каждой — свои клиенты, ставки налога, нумерация и реквизиты.
- **Счета**: номер `PREFIX-YY-M-NR` (например `ARV-26-8-1`), нумерация отдельная по каждому месяцу и бизнесу.
- Дата выставления по умолчанию — сегодня, срок оплаты — `+N` дней (настраивается на бизнесе), обе даты можно менять вручную.
- **Клиенты**: выбор из выпадающего списка с поиском по названию или рег. номеру; если не найден — ввод вручную (обязательны только название и рег. номер) с опцией сохранить в справочник.
- **Строки счёта**: описание, количество, сумма с переключателем `NET` / `INCL` (без налога / с налогом), ставка налога.
- **Ставки налога** — комбобокс: выбор из сохранённых или ввод новой, тогда предлагается «Создать ставку X%» и она добавляется в список. Дубликаты невозможны (уникальный индекс `businessId + rate`).
- Итоги: сумма без налога, разбивка налога по ставкам, итого к оплате.
- **Документ счёта** на выбранном языке (включая формат дат и сумм): логотип в левом верхнем углу, реквизиты выставителя, отдельным выделенным блоком — платёжные реквизиты (получатель, банк, IBAN, SWIFT, назначение платежа). Печать / сохранение в PDF — кнопка «Печать / PDF» (A4).
- **Дашборд**: счета сгруппированы по месяцам с итогами, фильтры по году, статусу и поиску.

## Локальный запуск

```bash
npm install
cp .env.example .env      # DATABASE_URL="file:./dev.db", AUTH_SECRET=...
npm run db:push
npm run seed              # админ из SEED_ADMIN_EMAIL / SEED_ADMIN_PASSWORD
npm run seed:demo         # опционально: демо-компания, клиенты и счета
npm run dev
```

Открыть http://localhost:3000. Если пользователей нет вообще — приложение само откроет `/setup` для создания первого администратора.

Полезное:

```bash
npm run db:studio   # Prisma Studio
npm run db:reset    # снести базу и пересоздать с чистым админом
```

## Языки

Их два независимых:

- **Язык панели** — `User.uiLanguage`, меняется в профиле. Словари лежат в [`lib/i18n.ts`](lib/i18n.ts):
  русский задаёт эталонную форму (`type Dict = typeof RU`), поэтому пропущенный ключ в эстонском
  или английском — ошибка компиляции, а не пустое место в интерфейсе. На каждый рендер язык
  читается из cookie, так что и экран входа локализован ещё до сессии.
- **Язык документа** — `Invoice.language`, выбирается на счёте, по умолчанию из `Business.defaultLanguage`.
  Подписи и форматирование дат/сумм берутся из [`lib/doc-language.ts`](lib/doc-language.ts).

Русская панель спокойно выставляет эстонские счета — это разные настройки.

## Модель доступа

Единственная граница разделения — `Business.ownerId`. Клиенты, ставки налога и счета
привязаны к компании, поэтому проверка владельца всегда сводится к
`business.ownerId === session.uid`. Все проверки собраны в [`lib/guard.ts`](lib/guard.ts):
страницы отдают 404 на чужой id (чужая запись неотличима от несуществующей),
server actions отказывают без записи. Ни один id из URL или формы не берётся на веру.

Удаление пользователя каскадом удаляет его компании, клиентов и счета — в админке об
этом предупреждает подтверждение.

## Деплой на Vercel (бесплатный тариф)

1. Завести бесплатную PostgreSQL-базу — проще всего Neon (см. таблицу выше).
2. Импортировать репозиторий в Vercel.
3. Задать в Project → Settings → Environment Variables:

   | Переменная               | Обяз. | Значение                                                        |
   | ------------------------ | ----- | --------------------------------------------------------------- |
   | `DATABASE_URL`           | да    | pooled-строка (хост с `-pooler`) — по ней идут запросы           |
   | `AUTH_SECRET`            | да    | вывод `openssl rand -base64 32`                                  |
   | `DATABASE_URL_UNPOOLED`  | жел.  | прямая строка (хост без `-pooler`) — по ней идут изменения схемы |

   Выставить для Production, Preview и Development — сборка падает без `DATABASE_URL`.
   Neon отдаёт обе строки на вкладке Connect; при подключении через Vercel Marketplace
   они добавляются автоматически.

4. Root Directory проекта — `arveland` (приложение лежит в подпапке репозитория).
   Framework Preset должен быть **Next.js**; на всякий случай это же зафиксировано
   в `vercel.json` — при пресете «Other» Vercel ищет статическую папку `public`
   и падает с `No Output Directory named "public" found`.
5. Deploy. Скрипт сборки сам определяет провайдера Prisma и делает `prisma db push` — миграции не нужны.
6. Открыть домен, `/setup` предложит создать первого администратора.

Схема Prisma одна на оба окружения: `scripts/db-provider.mjs` определяет провайдера по схеме `DATABASE_URL`
(`postgresql://` → postgresql, `file:` → sqlite). Переопределить можно переменной `DATABASE_PROVIDER`, но обычно
это не нужно. Если на хостинге `DATABASE_URL` не задан, сборка падает сразу с понятным сообщением, а не с
ошибкой валидации схемы Prisma.

Если задан `DATABASE_URL_UNPOOLED`, скрипт добавляет в схему `directUrl`: запросы идут через пул,
а DDL из `prisma db push` — напрямую, минуя pgbouncer (pgbouncer в transaction-режиме плохо переносит DDL).

## Структура

```
app/(app)/          защищённая часть: дашборд, счета, клиенты, компании, админка
app/login, /setup   вход и первичная настройка
components/         InvoiceEditor, InvoiceDocument, ClientPicker, TaxRateSelect, ...
lib/                prisma, auth/session, guard (владение), money (центы),
                    invoice (нумерация, даты), doc-language (ET/EN для документа)
prisma/schema.prisma
scripts/            db-provider, seed, demo
proxy.ts            защита маршрутов (бывший middleware)
```

Все денежные суммы хранятся целыми числами в центах; итоги пересчитываются на сервере при каждом сохранении, данные с клиента не принимаются на веру.
